      <h2>Lanes by blast radius</h2>
      <div class="table-wrap "><table><thead><tr><th>Lane</th><th>Checkout examples</th><th>Gate</th><th>Agent autonomy</th></tr></thead><tbody><tr><td>1. Reversible and contained</td><td>Copy, UI behind a flag, a support view, a new test</td><td>Deterministic checks, one human merge approval</td><td>Coding agent builds end to end</td></tr><tr><td>2. Human-authored change, human decision before execution</td><td>Suggestions in agent mode only</td></tr></tbody></table></div>

    <section class="doc-sec" id="start">
      <h2>Where to start</h2>
      <ol class="start-list"><li><strong>Pick one repeated flow</strong> For example, onboarding a product line&#x27;s promo rules. Draw the splitter, the lanes, the merge, one gate and one back edge.</li><li><strong>Build the gate first</strong> Locked acceptance tests and required checks. Everything gets easier once something can fail loudly.</li><li><strong>Then the lanes</strong> Label every issue lane 1, 2 or 3. Let Copilot coding agent take lane 1 issues end to end.</li><li><strong>Then the learning edge</strong> Once results are being accepted, turn each into a constraint in the brief and .github/copilot-instructions.md.</li><li><strong>Move the human to the last step</strong> Retire intermediate sign-offs; keep one accountable merge and ramp approval.</li></ol>
    </section>

          <div class="panel panel-future">
            <h2>What happens</h2>
            <p>The issue is assigned to Copilot coding agent. It works in its own environment, opens a draft pull request on a short-lived branch off trunk, and loops produce, check, correct until green. New behavior ships behind a feature flag.</p>
            <dl class="props">

              <div><dt>Human</dt><dd>None inside the loop. After three failed corrections the slice goes back to a person: the problem is in the plan, not the code.</dd></div>

    <section class="slide slide-roles" id="slide-roles">
      <h1>Copilot roles and human approval</h1>
      <p class="sub">Agents run the loops. A person approves only the last step: the merge, and the flag ramp where blast radius requires it.</p>
      <div class="callout"><strong>The one human step</strong> Put the human at the point of highest consequence and lowest reversibility. A human in the middle of the graph becomes its slowest node. Set the ruleset so the person who assigned the agent is not the only approver of its pull request.</div>
      <div class="table-wrap slide-table"><table><thead><tr><th>Step</th><th>Coding agent</th><th>Code review</th><th>Human</th></tr></thead><tbody><tr><td>Intake and slice</td><td>—</td><td>—</td><td>Approves slice plan, sets lane</td></tr><tr><td>Acceptance test first</td><td>Cannot edit acceptance/</td><td>—</td><td>Writes and locks the test</td></tr><tr><td>Build</td><td>Builds the slice, opens draft PR, loops to green</td><td>—</td><td>Takes back slices after 3 failures</td></tr><tr><td>Verify</td><td>Fixes the returned unit only</td><td>—</td><td>Platform group owns pipeline</td></tr><tr><td>Review and merge</td><td>Answers review comments</td><td>Reviews every PR first</td><td>Approves the merge (last step)</td></tr><tr><td>Release</td><td>Opens flag-ramp PR (lanes 1–2)</td><td>—</td><td>Approves lane 2 ramp; runs lane 3</td></tr><tr><td>Operate and learn</td><td>Drafts constraint and instruction PR</td><td>—</td><td>Accepts the constraint</td></tr></tbody></table></div>
      <div class="table-wrap slide-table"><table><thead><tr><th>Lane</th><th>Examples</th><th>Agent autonomy</th></tr></thead><tbody><tr><td>1 · Reversible and contained</td><td>Copy, UI behind a flag, a support view, a new test</td><td>Coding agent builds end to end</td></tr><tr><td>2 · Reversible but wide</td><td>Shared pricing library, API schema, fraud timeout</td><td>Agent builds; human approves merge and ramp</td></tr><tr><td>3 · Hard to reverse</td><td>Payment capture and refunds, ledger, card-data scope</td><td>Closed to agents. Suggestions only.</td></tr></tbody></table></div>
      <p class="lanes-note"><strong>Lane 3 stays closed.</strong> Payment capture, refunds, the ledger, and card data never open to agents. Lane 3 is not a high threshold — thresholds get adjusted; closed lanes do not.</p>
